01 · REACT

画面を部品にして、状態を記憶する

ReactではHTMLに似たJSXを使います。useStateはクリック回数など、変化する値を記憶します。

  • コンポーネント：再利用できる画面部品
  • Props：親から部品へ渡す情報
  • State：操作で変化する情報
Counter.jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      {count}回クリックしました
    </button>
  );
}
02 · NODE.JS

JavaScriptをブラウザの外で動かす

Node.jsを使うと、サーバー処理、ファイル操作、開発ツールの実行ができます。

  • サーバー：リクエストへデータを返す
  • npm：ライブラリを追加・管理する
  • package.json：プロジェクトの設定表
server.js
const http = require("http");

const server = http.createServer((req, res) => {
  res.writeHead(200);
  res.end("Node.jsからこんにちは！");

server.listen(3000);

REACT IN DETAIL

Reactの考え方を詳しく理解する

Reactは「画面を小さな部品に分け、データが変わったら表示を更新する」ための道具です。

COMPONENT & PROPS

部品を作り、外から情報を渡す

コンポーネントは大文字で始まる関数です。返り値としてJSXを書きます。Propsは関数の引数のようなもので、同じ部品へ異なる名前や色を渡して再利用できます。

  • コンポーネントは一つの役割に絞る
  • Propsは受け取った側で勝手に変更しない
  • 配列を表示するときは各要素へ一意なkeyをつける
ProfileCard.jsx
function ProfileCard({ name, job }) {
  return (
    <article className="card">
      <h2>{name}</h2>
      <p>{job}</p>
    </article>
  );
}

export default function Page() {
  return <ProfileCard name="佐藤" job="デザイナー" />;
}
JSXの注意： HTMLのclassはJSXではclassName、ラベルのforはhtmlForと書きます。JavaScriptの値は{ }で埋め込みます。

STATE & EVENT

ユーザー操作に応じて表示を変える

Stateはコンポーネントが記憶する値です。普通の変数を書き換えるだけではReactは画面を更新しません。useStateが返す更新関数を使います。

  • Stateは必要最小限にする
  • 前の値から更新するときは関数形式を使う
  • 入力欄はvalueとonChangeで状態に結びつけられる
TodoInput.jsx
import { useState } from "react";

function TodoInput() {
  const [text, setText] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    if (!text.trim()) return;
    console.log(text);
    setText("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={text}
        onChange={e => setText(e.target.value)} />
      <button>追加</button>
    </form>
  );
}

EFFECT

外部システムとの同期にuseEffectを使う

useEffectはAPI通信、タイマー、ブラウザAPIなど、Reactの外側との同期に使います。計算だけで求められる値をEffectでStateへ保存する必要はありません。

  • 依存配列[]なら初回表示後に実行
  • 依存値を入れると、その値が変化した後に再実行
  • タイマーや購読はクリーンアップ関数で解除
Clock.jsx
import { useEffect, useState } from "react";

function Clock() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const timer = setInterval(
      () => setNow(new Date()), 1000
    );
    return () => clearInterval(timer);
  }, []);

  return <time>{now.toLocaleTimeString()}</time>;
}

NODE.JS IN DETAIL

Node.jsが支えるもの

Node.jsはサーバーだけでなく、Next.jsの開発サーバー、ビルド、テスト、パッケージ管理も動かします。

npmとpackage.json

npm installで依存パッケージを追加します。package.jsonには名前、バージョン、実行コマンド、依存関係が記録されます。

モジュール

exportで公開し、importで別ファイルから利用します。役割ごとにファイルを分けると保守しやすくなります。

非同期処理

通信やファイル読み込みには時間がかかります。Promiseとasync / awaitで完了を待ち、try / catchで失敗を扱います。

APIからデータを取得する流れ

fetchはPromiseを返します。通信自体の失敗だけでなく、404や500などHTTPステータスも確認します。利用者へ見せるメッセージと、開発者が調査するログは分けて考えます。

秘密情報に注意： APIキーやパスワードをHTMLやGitHubへ直接書かないでください。サーバー側の環境変数へ置き、ブラウザへ送らない設計にします。
users.js
async function getUsers() {
  try {
    const response = await fetch("https://example.com/api/users");
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    return await response.json();
  } catch (error) {
    console.error("取得に失敗", error);
    return [];
  }
}

NEXT.JS IN DETAIL

画面とサーバーをどう分けるか

App Routerではコンポーネントは基本的にサーバーで実行されます。操作が必要な部分だけクライアントコンポーネントにします。

Server Component

データベースやAPIへサーバーからアクセスできます。秘密情報をブラウザへ送らず、送信するJavaScriptも減らせます。

Client Component

ファイル先頭に'use client'を書きます。State、イベント、ブラウザAPIが必要な部分で使います。

Route Handler

app/api/.../route.tsでGETやPOSTを受けるAPIを作れます。入力値の検証とエラー処理が重要です。

サーバーでデータを取得して表示する

サーバーコンポーネントはasync関数にでき、直接awaitできます。読み込み中はloading.tsx、見つからない場合はnot-found.tsx、予期しない失敗はerror.tsxで画面を分けます。

  • layout.tsx：複数ページで共有する枠
  • page.tsx：URLに対応するページ
  • [id]：商品番号など変化するURL部分
  • Link：ページを再読込せず移動するリンク
app/products/page.tsx
import Link from "next/link";

export default async function ProductsPage() {
  const response = await fetch(
    "https://example.com/api/products"
  );
  if (!response.ok) throw new Error("取得失敗");
  const products = await response.json();

  return (
    <ul>{products.map(product => (
      <li key={product.id}>
        <Link href={`/products/${product.id}`}>
          {product.name}
        </Link>
      </li>
    ))}</ul>
  );
}

DEBUGGING GUIDE

よくあるエラーの読み解き方

エラーメッセージを消すことではなく、原因を小さく切り分けることがデバッグです。

症状確認すること
Module not foundimport先のパス、ファイル名の大文字・小文字、パッケージのインストールを確認
... is not defined変数名のスペル、宣言位置、import漏れを確認
Hydrationエラーサーバーとブラウザで最初のHTMLが違っていないか、日時やランダム値を直接表示していないか確認
画面が更新されないStateを直接書き換えず、更新関数を使っているか確認
APIが401・403認証情報、権限、環境変数が正しいか確認。秘密情報を画面へ表示しない
基本手順： ターミナルまたはブラウザConsoleの最初のエラーを読む → ファイル名と行番号を見る → 直前の変更を確認 → 小さな範囲で再現 → 修正後に再実行、の順で進めます。
