01 · HTML

文書の意味と構造を伝える

HTMLは見た目ではなく、情報の意味を表します。見出しならh1、段落ならp、移動先がある文字ならaを使います。適切なタグを使うと、検索エンジンや音声読み上げにも内容が伝わりやすくなります。

  • headにはタイトルや文字コードなど画面に直接出ない設定を書く
  • bodyには見出し・文章・画像など画面に出る内容を書く
  • header、main、footerでページの大きな役割を分ける
  • 同じページ内でh1から急にh3へ飛ばさず、見出しの順番を守る
意味のあるHTML
<header>
  <h1>山田花子のポートフォリオ</h1>
  <nav><a href="#works">制作物</a></nav>
</header>
<main>
  <section id="works">
    <h2>制作物</h2>
    <article>
      <h3>カフェの紹介サイト</h3>
      <img src="cafe.jpg" alt="カフェ店内の写真">
      <p>HTMLとCSSで制作しました。</p>
    </article>
  </section>
</main>
属性役割
hrefリンクの移動先を指定
src画像など読み込むファイルを指定
alt画像が表す内容を短い言葉で説明
idページ内で重複しない目印をつける

02 · CSS

セレクタ・プロパティ・値で見た目を指定する

.card { color: navy; }では、.cardが対象を選ぶ「セレクタ」、colorが変更項目の「プロパティ」、navyが設定する「値」です。CSSが効かないときは、この3点とスペルを順に確認します。

  • 要素の実際の幅は、内容・余白・枠線の合計で決まる
  • box-sizing: border-boxで幅の計算が理解しやすくなる
  • 横並びにはdisplay: flex、格子状にはdisplay: gridが便利
  • スマホ対応では固定幅を避け、max-widthとメディアクエリを使う
content（内容）
内側：padding ／ 外側：border・margin
style.css
* { box-sizing: border-box; }

body {
  margin: 0;
  color: #222;
  font-family: sans-serif;
}

.cards {
  max-width: 960px;
  margin: 40px auto;
  padding: 0 20px;
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}

@media (max-width: 700px) {
  .cards { grid-template-columns: 1fr; }
}

試してみよう

gap: 20pxを40pxへ、画面幅の境界を700pxから900pxへ変え、表示の違いを観察しましょう。

03 · JAVASCRIPT

入力を受け取り、判断し、画面を変える

JavaScriptの基本は「値を記憶する」「処理をまとめる」「条件で分ける」です。ブラウザではDOMという仕組みを通してHTML要素を探し、文章やクラスを変更できます。

  • constは再代入しない値、letは後で変更する値に使う
  • 関数は何度も使う処理へ名前をつけたもの
  • ifで条件に応じて実行内容を変える
  • addEventListenerでクリックや入力を受け取る
button-example.js
const button = document.querySelector('#hello');
const message = document.querySelector('#message');
let count = 0;

function showMessage() {
  count = count + 1;
  if (count === 1) {
    message.textContent = 'はじめてのクリック！';
  } else {
    message.textContent = `${count}回クリックしました`;
  }
}

button.addEventListener('click', showMessage);
コード意味
querySelectorCSSセレクタでHTML要素を探す
textContent要素内の文字を読み書きする
===値と型が同じか厳密に比較する
${...}文字列の中へ値を埋め込む

GOOD WEB PRACTICES

公開前に知っておきたい品質の基本

「表示できる」から一歩進んで、誰にとっても使いやすいページを目指します。

アクセシビリティ

画像に適切なaltをつけ、ボタンはdivではなくbuttonで作ります。キーボードだけでも操作できるか確認します。

レスポンシブ

ブラウザ幅を狭くして、文字が小さすぎないか、横スクロールが出ないか、ボタンが押しやすいかを確認します。

読み込み速度

画像は必要以上に大きくせず、用途に合った形式とサイズへ調整します。不要なフォントやライブラリも増やしすぎないようにします。

開発者ツールの使い方

ブラウザで右クリックして「検証」を開きます。ElementsではHTMLとCSS、ConsoleではJavaScriptのエラー、Networkでは読み込んだファイルを確認できます。赤いエラーが出たら、最初の1件を読み、ファイル名と行番号から直すのが基本です。

PUBLISH CHECKLIST

GitHubへ置く前の確認

公開後に困らないよう、次の項目を一つずつ確認します。

確認項目見るポイント
✓ ファイル名入口のページはindex.html。大文字・小文字も区別する
✓ リンクすべてのリンクとページ内移動を実際にクリックする
✓ 画像パスが正しく、画像がなくても意味が伝わるaltがある
✓ スマホ表示狭い画面で横にはみ出さず、文字とボタンが十分な大きさ
✓ 表記誤字、仮の文章、個人情報、公開してはいけない鍵やパスワードがない

WHEN YOU GET STUCK

動かないときの確認リスト

01保存した？

変更後はまず保存。エディタのタブに丸印があれば未保存の合図です。

02ファイル名は正しい？

index.html.txtではなくindex.htmlか確認します。

03記号が抜けていない？

閉じタグ、かっこ、引用符が左右そろっているか確認します。

04ブラウザを更新した？

保存後は再読み込みボタンを押して最新の表示にします。
